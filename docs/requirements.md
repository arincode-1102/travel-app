# 旅行管理アプリ MVP 要件

- 作成日: 2026-09-27
- 最終更新: 2026-09-27（改訂1: 移動メモ廃止 / 開始・終了時刻 / 予定メモ追加）
- 種別: 個人学習用 / サーバーなし / データはブラウザ内のみ

---

## 1. 目的

旅行の予定と持ち物を1か所にまとめ、**旅行中にスマホで開いて「今日の予定」をすぐ確認できる**ようにする。

解決したい不便:

| # | 不便 | いつ困るか |
|---|---|---|
| A | 旅行の予定が1か所にまとまっていない | 旅行前の計画中 |
| B | 旅行中に「次どこ・何時・どう行く」をすぐ出せない | **旅行当日（最重要）** |
| C | 持ち物を毎回思い出しながら詰めて、結局忘れる | 出発前日 |

## 2. MVPの価値

> 自分の次の旅行の「1日ごとの予定」と「持ち物」を、出発前に登録して、旅行中にスマホで開いて確認できる。

## 3. 完成条件

1. 次の旅行1件について、日程・予定・持ち物を登録できる
2. 旅行当日、開いて3秒以内に「今日の予定」が読める
3. 出発前日、持ち物にチェックを付けながら荷造りできる
4. ブラウザを閉じて開き直してもデータが残っている

## 4. データ構造

```
旅行（複数件）
├ id
├ 旅行名                              必須
├ 開始日 / 終了日                      必須（日数はここから自動計算）
├ 日（開始日〜終了日で自動生成）
│  ├ 日付
│  └ 予定（複数）
│     ├ 開始時刻                      任意
│     ├ 終了時刻                      任意
│     ├ 内容                          必須
│     ├ 場所                          任意
│     └ メモ                          任意（乗り場・予約情報・注意事項・URL など）
└ 持ち物（複数・旅行単位）
   ├ 名前
   └ チェック状態
```

### 予定（Plan）の扱い

- **移動も予定として登録する。** 電車・バス・徒歩・送迎は観光や食事と交互に時系列で発生するため、
  日単位の「移動メモ」は持たず、すべて同じ予定として並べる。
  - 例: 大阪駅 出発 / 特急に乗車 / 城崎温泉駅 到着 / ホテルへ徒歩移動 / チェックイン / 観光
- **時刻は開始・終了とも任意。** 終了時刻のない予定があるため、どちらも必須にしない。
  - 例: `08:14 特急出発` / `11:00〜15:00 温泉街散策` / `時刻なし お土産を見る`

### 予定の並び順

1. 開始時刻が設定されている予定を、開始時刻の昇順で先に表示する
2. 開始時刻がない予定は、そのあとに追加順で表示する

## 5. 画面

| 画面 | 内容 |
|---|---|
| ① ホーム | 旅行カードの一覧（旅行名・日付）／「＋新しい旅行」／各カードから削除 |
| ② 旅行詳細 | `日程` / `持ち物` の2タブ。日程タブは日別に区切り、当日の日付を開いた状態にする。旅行中に開く画面 |
| ③ 編集 | 旅行名・日付の編集。予定と持ち物の追加・編集・削除 |

## 6. 機能一覧

- 旅行: 作成 / 編集 / 削除（削除は確認ダイアログあり）
- 予定: 追加 / 編集 / 削除（開始時刻・終了時刻・内容・場所・メモ）
- 持ち物: 追加 / 編集 / 削除 / チェック
- 保存: localStorage に自動保存（保存ボタンなし）
- 表示: スマホ幅を基準（PCでも崩れない程度）

## 7. 今回やらないこと

### 仕組みとして作らないもの
ログイン / オンライン共有 / 地図API / 外部API / クラウドDB / AI機能 / 決済 / 他ユーザー投稿 /
JSON書き出し・読み込み / 予定の並べ替えD&D / 持ち物のカテゴリ分け / 写真添付 / 費用管理 / 持ち物テンプレート

### 専用の項目を作らず「予定のメモ」で代用するもの
天気 / 服装 / 予約ステータス / 費用 / 予定のカテゴリ分け / 重要度・デッドライン専用項目 / 写真 /
地図 / URL専用項目 / 候補スポット一覧 / 同行者別の担当管理

→ 実際にMVPを使ったうえで、必要性を判断する。

## 8. 受け入れる制約

- データはそのスマホのそのブラウザにだけ残る。ブラウザの「閲覧データを削除」で消える。
- PCで入力したものはスマホに出てこない（今回はスマホで入力する運用）。
- バックアップ手段はない。必要になったら、あとからJSON書き出しを追加するのが最短。

## 9. 決定事項の記録

| 論点 | 決定 | 理由 |
|---|---|---|
| 利用端末 | スマホで入力・スマホで閲覧 | localStorage は端末をまたげないため。追加実装ゼロで完成条件を満たせる |
| 予定の時刻 | 開始・終了とも任意入力 | 旅行中に「次は何時か」が要る一方、終了時刻が決まらない予定も多いため |
| 旅行の件数 | 複数件を一覧で管理 | 1件固定でも実装は簡単にならず、次の旅行で前回が消えるため |
| 移動の扱い | 日単位の移動メモは持たず、予定として登録（改訂1） | 移動は1日1つではなく、観光や食事と交互に時系列で発生するため |
| 予定の補足情報 | 自由記述のメモ欄1つで受ける（改訂1） | 乗り場・予約情報・注意事項・URLなど種類が多く、専用項目化は使ってから判断したいため |
